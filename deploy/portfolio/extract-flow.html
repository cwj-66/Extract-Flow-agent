01 / 产品功能

从一份 PDF，走到可确认的摘要。

自动化完成整理与初步提取，把需要判断的内容留在审阅界面。原文、字段与投递结果能够在同一条任务记录里查找。

01 / UPLOAD

单份与批量上传

上传一份 PDF，或按文件夹批量提交。任务异步执行，工作台展示各份文档的状态与批次进度。

02 / PARSE

正文与图表解析

MinerU 云端解析正文、表格与公式，生成 Markdown；视觉模型补充图像描述，保留结构化文档条目。

03 / EXTRACT

15 个结构化字段

从公司、评级、业绩预测到风险提示，使用固定 Schema 提取研报摘要，便于后续核对与复用。

04 / REVIEW

原文对照与人工修改

并排查看解析原文和提取字段。检查预测、评级与关键观点，修改结果后选择投递群。

05 / DELIVERY

确认后发送飞书

使用数据库中的群配置构建飞书 Card v2。提取完成时停在待确认，投递失败时显示原因并支持重试。

06 / TRACE

历史、导出与审计

按公司、文件名与状态检索任务，下载原始文件，导出已确认发送的字段，查看处理与修改记录。

02 / 处理架构

解析、提取与确认，各有自己的边界。

HTTP 接口负责接收操作，服务层管理任务状态，共享管线执行文档处理。耗时任务进入队列，页面通过轮询获取进度。

一条管线，多个入口

CLI、API 与可选 Celery 入口复用同一套 PipelineService 和处理编排。路由层只负责 HTTP 映射，业务逻辑集中在服务层。

把模型计算放在云端

线上调用 MinerU 和 DashScope，服务器负责文件、任务和页面，不常驻加载模型权重。适合与客服 Agent 共用 4GB 服务器。

04 / 并发与稳定性

多人同时上传，按容量处理。

服务进程与连接池由访客共享，每份研报仍有独立的解析与模型请求。线上限制执行名额、等待队列与提交频率，让研报有序处理，也为共用的 4GB 服务器留出内存。

1份同时执行的完整研报任务
10份最多等待处理的研报
5次 / 分钟每个登录访客的提交上限
30次 / 分钟每个 IP 的提交上限
5 位访客各上传 1 份研报 → 1 份执行、4 份按入队顺序等待；任务完成或失败后释放名额，下一份继续。总容量满时返回 503 与重试时间，整批上传先预留全部名额，避免容量不足造成半批提交。

有界队列与容量预留

单个 API 进程维护 FIFO 队列，执行、等待和上传预留共享 11 个名额。上传落盘前检查容量，批量提交一次预留；未使用的名额在失败时归还，不无限堆积任务。

Redis 原子限流与故障保护

Lua 脚本一次检查登录会话与 IP，允许后才同时计数；窗口从首次提交开始，60 秒后到期。Redis 暂不可用时，新上传返回 503，历史查询与原文审阅仍可使用。

访客限流与可信代理

超过提交频率返回 429 和 Retry-After，工作台展示建议重试时间。身份取自经作品集验证的登录会话，转发 IP 由入口代理覆盖，计数键只保存摘要。

下游超时与有限重试

MinerU 云端解析总等待上限为 1200 秒；模型请求超时配置为 90 秒，临时网络或服务错误最多重试 2 次，JSON 格式修复最多 1 次。90 秒不代表整份任务总时限，失败原因保存到任务记录。

内存控制与阻塞操作隔离

PDF 按 1MB 分块保存，耗时管线在线程中执行；每份研报最多并发描述 2 张图像。容器分别设置内存上限，MinerU 与 qwen3.8-27b 在云端运行，服务器不加载模型权重。

执行结束后回收名额

管线完成或失败后归还处理容量；正常关闭时等待正在运行的同步管线结束。任务状态与结果写入 Postgres，可重开页面查看；进程内排队不承诺重启后自动续跑。
